# Skyline Cadenza v26.3.0 Release Notes

Feature release that makes MTM scheduling co-isolation aware, adds DIA-NN + Carafe backfill and predicted peptide ranking, and adds forced peptides, a rank cap, and a per-slot target cap.

## New Features

### MTM co-isolation

- **Added a "Minimum target share of window current" slider** (under MTM constraints; default 1.5%, 0 = off). The scheduler no longer places a target in a window where co-isolated ions would take so much of the fill that it cannot be quantified. Every target in the slot is checked over its own elution rather than only the smallest one, since each target has its own competition. The competition is every identified precursor inside the emitted isolation band, targeted or not, because most of the current a window admits comes from precursors that were never targets. Each competitor counts only for the part of its peak that co-elutes with the target, so a large neighbour clipping the edge of a peak is not treated like one sitting on top of it. The share is computed over the integrated peak rather than at individual time points, because a target is quantified from its whole peak and Cadenza has no peak-shape model. A rejected target falls through to its protein's next peptide, so the usual effect is a cleaner peptide for that protein rather than a lost protein. Predicted-only targets have no measured intensity and are exempt. Only identified precursors are counted, so the estimate is a lower bound on the true co-isolation.
- **The fragment clash check now covers co-isolated background**, not just a slot's own targets. Before, it only compared a joining target's top-4 fragments with the other targets in the slot, and solo windows were never checked. A placement is now refused if any of a target's top-4 fragments picks up at least 1% of its own signal from co-eluting identified precursors inside the band, each weighted by how much of its peak co-elutes with the target. Only the interferers' top-4 fragments are compared; comparing against their full fragment lists rejected far too many targets. The 1% tolerance is fixed so that a much weaker background precursor cannot block a target. This is always on and has no control.
- **Added passengers**: precursors that already fall inside a scheduled window's isolation band and elute entirely within its firing time. The instrument fragments them either way, so listing them costs no cycle time and changes nothing in the exported Thermo method. They are admitted after the schedule is final and never change a window, so the rules that shape windows (same charge per slot, fragment clash, the per-protein maximum) do not apply to them. A passenger needs full RT containment and at least 5% of the band's co-isolated current. The new **"Include passengers in Skyline push"** checkbox (off by default) chooses between a targets-only document and a targets-plus-passengers document. Passengers are tagged `passenger` in the transition list.
- **Added a "Max targets per slot" slider** (under MTM constraints; 0 = no cap, the default). It caps how many targeted precursors one MTM window can multiplex. A target that would join a full window goes to another window, opens its own, or falls through to its protein's next peptide. Untargeted co-isolated precursors and passengers do not count against the cap.

### Carafe predictions

- **Added a DIA-NN + Carafe backfill mode** (checkbox "Backfill unused schedule time with Carafe predictions"; needs both a DIA-NN report and a Carafe library). Confirmed DIA-NN targets are scheduled first. Carafe-predicted targets then fill whatever cycle budget is left, deduplicated against the confirmed targets by peptide and charge. Predictions are limited to the proteins DIA-NN observed plus any target protein list, so they add depth to confirmed proteins and cover proteins DIA-NN missed. Predicted targets follow the same cycle budget and per-protein maximum as confirmed ones. The confirmed schedule is identical whether or not a Carafe library is loaded: predictions can only add targets, never move, drop, or reorder a confirmed one.
- **Added a "Carafe detectability predictions" input** (files or a folder of shards) with a **"Detectability cutoff" slider** (default 0.5). Precursors below the cutoff are dropped before scheduling; peptides with no prediction are kept.
- **Added a "Bromo peptide ranking" input** for ranking peptides within a protein in Carafe-only mode. When no Bromo file is loaded, Carafe detectability ranks the peptides instead. Either replaces the old fragment-intensity stand-in, which carried no detectability signal. The ranking is within-protein only and never affects protein order, since predictions give no cross-protein abundance.
- **Added a "Predicted peak half-width (Carafe)" slider** (default 6 s), replacing the hardcoded 0.10 min synthesised peak. It applies only to Carafe-predicted precursors; DIA-NN and Skyline inputs use their measured peak boundaries.

### Target selection

- **Added forced peptides**: a list of peptides (text box or "Open peptide list...", one per line, with an optional charge) that is scheduled before anything else. Use it to carry the same validation peptides or intentional targets across schedules. Forced peptides obey every quality and instrument rule but ignore ranking, the rank cap, the per-protein bounds, and an exclusive target list. Each is placed the normal way under the schedule's own parameters, so the same core set can be compared across schedules built with different settings. An entry with no charge tries its best charge state first and falls back to the others. The rest of the fill never drops a forced peptide. The status line lists entries that were not in the library or failed a rule.
- **Added a "Rank cap: top N per protein" slider** (under Peptide ranking; 0 = no cap, the default). Only each protein's top N precursors, by the selected peptide ranking, are eligible for scheduling. It counts precursors, so one peptide at two charge states uses two of the N. This is different from "Maximum peptides per protein": the rank cap shrinks the pool that scheduling chooses from, while the maximum limits how many of the eligible peptides are scheduled. In backfill mode the cap is applied separately to the confirmed and predicted peptides.

### Command-line tool

- `SkylineCadenza.Cli` gained a `schedule-diann REPORT.parquet PARAMS.json OUTPUT.json` command that runs the app's DIA-NN ingest before scheduling, for offline comparisons. The JSON input also accepts `forcedPeptides`, `peptideRankCap`, `minTargetIonShare`, `backgroundFragmentClash`, and `maxTargetsPerSlot`.

## Bug Fixes

- **Loading a Carafe library no longer changes the confirmed schedule.** In backfill mode the predicted peptides leaked into the confirmed schedule in several ways: protein grouping ran over DIA-NN and Carafe peptides together, predicted peptides changed each protein's ranking and window growth limits, a prediction could evict a confirmed target from a window, and turning backfill on switched the confirmed peptides' ranking to a predicted score they don't have. Loading Carafe also replaced the confirmed peptides' measured DIA-NN fragments with Carafe's predicted ones, even with backfill off. Protein grouping now runs over DIA-NN evidence only, with predicted peptides assigned to the confirmed groups by accession; everything that orders or shapes the confirmed schedule is computed from confirmed peptides only; confirmed peptides keep their measured fragments; and turning backfill on no longer overwrites your peptide ranking choice.
- **Scheduling is now reproducible across launches.** Peptides that tied on the ranking metric were ordered by the order the candidate list happened to arrive in, and for Carafe libraries that order changed on every launch. Identical inputs and settings could produce a different schedule each time, so an exported target list and a Skyline document built from it could silently disagree. Ties are now broken by precursor ID and Carafe candidates load in a fixed order. Schedules with fully distinct ranking scores were already reproducible.
- **Fixed "No valid precursor m/z column found, line 1" when pushing a document that contains heavy-labeled standards** such as spiked PRTC. Heavy precursors are now left out of the transition list (they already reach the assay through the registered spectral library). The import also skips unexpected rows instead of discarding the whole assay. The status line reports how many heavy precursors were omitted.

## Breaking Changes

- **Removed the "Window packing" setting and its Legacy mode.** MTM windows are now always packed so that a window never grows across a co-eluting precursor that clashes with one of its members, and two windows firing at the same time never overlap in m/z. The old Legacy default allowed both, so windows could sweep over precursors they had just rejected and re-sample the same precursors at a fraction of the sensitivity. This lowers raw target and protein counts in exchange for windows that isolate what they claim to. The CLI no longer reads a `packing` field; a request that still sets it is accepted and the field is ignored. Schedules made before this change can't be reproduced.
